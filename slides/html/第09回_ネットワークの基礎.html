到達目標

3
9.1

データの届け方

回線を占有するか、小分けにして混ぜるか

9.1　パケット交換

回線交換とパケット交換

計算機の通信はバースト的である。読んでいる間ずっと回線を占有するのは、極端に効率が悪い。

パケット交換にはもう1つ、耐障害性という設計思想上の利点がある。
インターネットの原型 ARPANET（1969年）では「網の一部が失われても通信が続くこと」が設計目標の1つだった。

5
9.1　パケット交換

ベストエフォート

パケット交換の帰結として、インターネットは「届けるために最善を尽くすが、保証はしない」サービスを提供する。

失われる
混雑時、回線の障害でパケットが消える
順番が入れ替わる
別々の経路を通るため
遅延が変動する
経路上の混雑状況による
重複して届く
同じデータが2度届くことがある
では、なぜファイル転送や決済ができるのか
答えは階層である。下の層が保証しないことを、上の層（第10回の TCP）が補う。この分業が次節の主題である。

9.2

階層モデル

問題を層に分け、各層を独立に改良する

9.2　階層モデル

TCP/IP 階層モデル

理論的には OSI 参照モデル（7層）が知られているが、実際のインターネットはこちらで動いている。

層役割主なプロトコルデータの呼び名
アプリケーション層アプリ固有のやりとりHTTP, DNS, SMTP, SSHメッセージ
トランスポート層端点間の通信の品質TCP, UDP, QUICセグメント
インターネット層網をまたぐ中継IP, ICMPパケット
データリンク層隣の機器への配送Ethernet, Wi-Fiフレーム
物理層ビットを信号に各種ケーブル、電波ビット

利点は3つ。各層を独立に設計・改良できる／下の層が変わっても上は影響を受けない／上の層が増えても下は影響を受けない。
光ファイバに替えても Web ブラウザを書き直さなくてよい。

第3回のゲート→CPU、第4回の機械語→高級言語、第8回のドライバと同じ構図である。

9.2　階層モデル

カプセル化

上の層のデータは、下の層のデータの中身として運ばれる。各層は自分のヘッダを付け加える。

封筒の比喩：手紙を書き、封筒に何通目かを書き、宛先住所を書き、配送業者の伝票を貼る。

9
9.2　階層モデル

階層を降りて、上がる

配送業者は手紙の中身を読まないし、手紙の書き手は伝票番号を知らない。
この独立性が階層の価値である。

9.3

インターネットの構造

中央の管理者がいない「網の網」

9.3　構造

インターネットは「網の網」

インターネットは単一の巨大なネットワークではない。独立に運営される多数のネットワーク（AS）が相互接続したものである。

中央の管理者がいない。誰も全体像を把握していない。それでも「どこからでもどこへでも」届く。

12
9.3　構造

接続の形と IX

トランジット
下位の事業者が上位に費用を払い、インターネット全体への到達性を買う
ピアリング
対等な事業者どうしが、互いの顧客宛の通信を無料で交換する
IX（相互接続点）
多数の事業者が物理的に集まり相互接続する拠点。日本では JPIX、JPNAP など
IX の意義
n 個の事業者が互いに接続するには n(n−1)/2 本の線が要る。IX に集まれば n 本で済む。

1990年代には国内どうしの通信が米国を往復していた。IX の整備は、通信の効率と主権の両面で意味を持つ。

13
9.3　構造

スケールフリーネットワーク

インターネットの接続構造は、少数の非常に多く接続されたノードと、多数の少ししか接続されていないノードからなる。

ランダムな故障に強い

でたらめにノードが壊れても、大半は末端のノードなので、全体の連結性は保たれる。

狙った攻撃に弱い

ハブとなるノードを狙って落とすと、網が急速に分断される。

「六次の隔たり」も、少数のハブが遠い領域どうしを橋渡しすることで説明される。インターネットの経路長も、規模の割に驚くほど短い。

14
9.4

物理層とデータリンク層

ビットを信号にし、隣の機器へ届ける

9.4　物理層

ツイストペアが撚ってある理由

媒体
  • ツイストペアケーブル — 安価。100m 程度まで
  • 光ファイバ — 長距離・大容量・電磁ノイズに強い
  • 電波 — 配線不要。共有媒体なので干渉と盗聴の問題がある
撚る効果

2本の線を撚ると、外部からのノイズが両方の線にほぼ同じだけ乗る。受信側で2本の差を取れば、共通に乗ったノイズが打ち消される。

また、自分自身が発する電磁波も互いに打ち消し合う。

単純な工夫で、雑音に強い伝送路を安く作っている。第2回の「2値なら多少ばらついても識別できる」と合わせて、デジタル通信の頑健さの源になっている。

16
9.4　データリンク層

MAC アドレスと IP アドレス

データリンク層は「同じネットワーク内で直接つながっている機器」へデータを届ける。単位はフレームである。

MAC アドレスIP アドレス
層データリンク層インターネット層
範囲同じネットワーク内インターネット全体
割り当て製造時に固定（48ビット）ネットワークへの接続時に決まる
構造場所の情報を持たない階層的で、場所を表す
比喩個人の指紋現在の住所
なぜ2つ要るのか

世界中の全機器の位置を各機器が覚えるのは不可能である。IP アドレスは階層的なので「この方向へ送れ」という
粗い判断ができ、最後の1ホップだけ MAC アドレスで特定する、という分業が成立する。

17
9.4　データリンク層

Ethernet

有線 LAN の事実上の標準。1970年代に開発され、速度を上げながら50年間使われ続けている。

速度の世代
規格速度主な用途
1000BASE-T1 Gbps一般的な有線 LAN
10GBASE-T10 Gbpsサーバ、拠点間
100/400GbE100/400 Gbpsデータセンタ、基幹
フレームの構造
| 宛先MAC (6) | 送信元MAC (6) |
| 型 (2) | データ (46-1500) |
| FCS (4) |

FCS は誤り検出用。計算が合わなければフレームを捨てるが、訂正はしない。再送は上の層（TCP）に任せる。

初期の CSMA/CD は、1本の同軸ケーブルを全機器で共有していた時代の仕組み。現在のスイッチ構成では衝突は起きない。

9.4　データリンク層

スイッチは自分で学習する

中央の管理者なしに、局所的な観察だけで効率的な転送を実現している。

9.4　無線

Wi-Fi：共有媒体ゆえの問題

無線 LAN（IEEE 802.11 系）は電波という共有媒体を使うため、有線とは異なる問題を抱える。

衝突を検出できない
送信中は自分の電波で相手の電波が聞こえない。送る前に一定時間待つ方式（CSMA/CA）を使う
隠れ端末問題
A と C が互いの電波は届かないが、両方とも B に届く場合、互いの送信に気づかず衝突する
帯域を分け合う
同じアクセスポイントの利用者が増えると、帯域が分割される
傍受されうる
電波は誰にでも届く。暗号化が必須（WPA3 を使う。WEP と WPA は破られている）

現在は通信そのものが TLS で暗号化されているため（第10回）、公衆 Wi-Fi の危険性は昔より小さくなっている。

9.5

インターネット層：IP

網をまたいで、最終的な宛先まで中継する

9.5　IP

IPv4 アドレスは2つの部分に分かれる

IPv4 アドレスは32ビット、全部で約43億個。境界を示すのがサブネットマスクである。

192.0.2.130/24 の内訳
アドレス  192.0.2.130
  = 11000000 00000000 00000010 10000010
マスク /24
  = 11111111 11111111 11111111 00000000
ネットワーク  192.0.2.0
ホスト部      .130
なぜ階層構造にするのか

経路表を小さくするため。世界中の43億個を1つずつ覚えることはできないが、「192.0.2.0/24 宛はあちらへ」とまとめれば1行で256個分を表せる。

割り当てられるのは 254 個

先頭（ネットワーク自体）と末尾（ブロードキャスト）は使えない。9.4 の「IP は住所」とはこの階層性のことである。

22
9.5　IP

ルーティング：最長一致で選ぶ

ルータは複数のネットワークにまたがって接続され、経路表を引いて次のルータへ渡す。

宛先ネットワーク次の転送先出ていくインタフェース
192.0.2.0/24直接接続eth0
198.51.100.0/24203.0.113.1eth1
0.0.0.0/0（デフォルト）203.0.113.254eth1
複数の行に当てはまる場合、もっとも細かく指定している行を選ぶ

デフォルトルートはどのアドレスにも当てはまるがプレフィクスが最短なので、他に該当がないときだけ使われる。
TTL はルータを通るたびに1減り、0 で破棄される。経路が輪になっていても永遠に回り続けない。

9.5　IP

アドレスの枯渇と NAT

43億個は世界人口を下回る。IPv4 アドレスの新規割り当ては2011年以降、順次枯渇している。

根本的な解決は IPv6（128ビット、約 3.4×10³⁸ 個）。地球の全表面 1cm² あたりに 10²² 個以上を
割り当ててもまだ余る。IPv4 と IPv6 は直接相互運用できないため、当面はデュアルスタック運用が続く。

まとめ

  • パケット交換回線を占有せず経路の障害に強いが、遅延も到達も保証しない（ベストエフォート）
  • 階層モデル問題を分割し、各層を独立に改良できる。データは層を降りるごとにヘッダで包まれる
  • インターネット独立した多数の AS が相互接続した「網の網」。中央の管理者はいない
  • スケールフリーランダム故障に強く、ハブへの攻撃に弱い
  • 2種類のアドレスMAC は「隣の機器」、IP は「世界のどこか」を指す。役割が違うので両方要る
  • スイッチ送信元 MAC を観察するだけで、転送表を自律的に学習する
  • IPアドレスは階層構造を持つので経路表を小さく保てる。ルータは最長一致で選ぶ
