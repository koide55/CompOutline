1.1

アルゴリズム

手順を、曖昧さなく書き下すとはどういうことか

1.1　アルゴリズム

アルゴリズムの定義

1. 有限性
有限の手数で必ず終わる
2. 明確性
各ステップが曖昧さなく定まっている
3. 入力
0個以上の入力を受け取る
4. 出力
1個以上の出力を返す
5. 実行可能性
各ステップが機械的に実行できる
「明確さ」の要求は、思っているより厳しい
料理のレシピにある「塩少々」は、アルゴリズムの条件を満たさない。実行する人の判断が入る余地があってはならない。

1.2　チューリングマシン

なぜこんなものを考えるのか

「計算できる」を「アルゴリズムがある」で定義すると、「機械的に実行できる」という曖昧な言葉が残る。堂々巡りである。しかも1928年にヒルベルトが提起した決定問題 ——「数学の命題が証明可能かを機械的に判定できるか」—— に答えるには、これを片づける必要があった。

読む
紙のどこか1箇所を見て、書いてある記号を読む
決める
頭の中の「今どういうつもりか」と、読んだ記号から次にすることを決める
書く
そこに記号を書く。消して書き直すこともある
動く
視線を隣に移す
チューリングが1936年にとった方針
人間が紙と鉛筆で計算しているとき、その人は実際には何をしているのか。それを極限まで単純化した機械を作れば、その機械ができることが「計算」である。

これを機械にしたものがチューリングマシン。部品はテープ・ヘッド・有限個の状態しかない。

1.2　チューリングマシン

設計の手順：状態とは「覚えていられること」である

チューリングマシンには変数がない。記憶できる場所はテープと状態しかなく、しかも状態は有限個しかない。

1
何を覚えるか決める
その種類の数が、そのまま状態の数になる
2
各状態の動作を書く
記号を読んだときに、何を書き・どちらへ動き・次はどの状態か
3
いつ止まるかを決める
停止状態に入る条件

覚えることが何もなければ状態は1つでよい（例：0 を全部 1 に書き換えて、空白で止まる機械）。
「1 の個数が偶数か奇数か」を判定するには状態が2つ要る。個数そのものは覚えられないが、偶奇なら2つで足りる。

覚えることの数が、状態の数を決める。これが設計のほとんど唯一のコツである（演習1-2）。

1.2　チューリングマシン

万能チューリングマシン

ここまでの機械は「1を足す」専用だった。ところがチューリングは、他のチューリングマシンの遷移規則表そのものをテープに書いて渡すと、それを解釈して真似する機械が作れることを示した。

専用機を作り分けるのではなく、1台の機械に「何をするか」をデータとして与える
  • テープに書かれた規則表 プログラム
  • それを解釈して実行する万能機 CPU
  • 同じテープに置かれる入力 データ

プログラムとデータが同じ場所に同じ形式で置かれる —— 第3回のノイマン型の原型が、ここにある。

1.3　計算の限界

チャーチ＝チューリングのテーゼ

発想はばらばらなのに、計算できる関数の集合はぴったり一致する。

モデル提案発想
チューリングマシンTuring, 1936紙と鉛筆の計算を機械化する
λ計算Church, 1936関数の適用だけで計算を表す
帰納的関数Gödel, Kleene, 1930s基本関数と再帰から組み立てる
レジスタマシンShepherdson–Sturgis, 1963無限個のレジスタを操作する
セルオートマトンvon Neumann, 1940s単純な規則で更新される格子
「直観的に計算可能」な関数は、チューリングマシンで計算可能な関数と一致する

使う言語やハードウェアを変えても、計算できる問題の範囲は広がらない。
Python でできて C でできないことはないし、GPU を1万個並べても同じである。

1.3　計算の限界

量子計算機は、この話を変えるか

量子チューリングマシンは、通常のチューリングマシンと同じ範囲の関数を計算することが示されている。チャーチ＝チューリングのテーゼは、いまのところ破られていない。

変わるのは「何が計算できるか」ではなく、「どれだけ速く計算できるか」である
  • 計算できる範囲 変わらない
  • 計算の速さ 変わりうる
  • 停止問題 解けないまま

Shor (1994) は素因数分解を多項式時間で解く。古典計算機では効率的な方法が知られていない。
Grover (1996) はしらみつぶし探索を √n 回に減らす。速さをどう測るかは第2回で扱う。

現在の公開鍵暗号は、素因数分解が効率的に解けないことに安全性を託している（第12回）。

1.3　計算の限界

停止問題

プログラム P と入力 x が与えられたとき、「P に x を入力して実行すると、いつか停止するか」を判定せよ。これを判定する halts(P, x) は存在しない。

trouble(P):
    if halts(P, P):        # P に P 自身を入力すると停止するか
        while True: pass   # 停止するなら、わざと無限ループする
    else:
        return             # 停止しないなら、さっさと停止する

停止する とすると　halts は真を返す → trouble は無限ループに入る → 停止しない。矛盾
停止しない とすると　halts は偽を返す → trouble はすぐ return する → 停止する。矛盾

どちらでも矛盾する。よって仮定が誤りで、halts は存在しない。

1.3　計算の限界

対角線論法

対角線をすべて反転させたものが trouble の振る舞い。どの行とも1マス以上食い違う。

1.1 で見たコラッツの手順が、なぜ90年も未解決なのかが、これで少し見える。
停止するかどうかを機械的に判定する一般的な方法が、そもそも存在しない。

1.3　計算の限界

決定不能な問題は、他にもある

ライスの定理：プログラムの入出力の振る舞いに関する自明でない性質は、すべて決定不能である。だからコンパイラの警告は見逃すし、テストはバグの不在を証明できない。

近似する
「危ないかもしれない」を過剰に報告する（静的解析の偽陽性）
対象を狭める
決定可能な範囲に制限する（型システム、正規表現）
人間を入れる
判断を人に委ねる

技術が未熟だからではなく、原理的にそうである。現場ではこの限界を、こう迂回する。

1.3　計算の限界

では、生成AI は停止問題を解いているのか

「このプログラムは停止しますか」と生成AIに聞けば答えが返る。静的解析ツールも「ここでヌル参照が起きうる」と教えてくれる。これは停止問題を解いたことにならないのか。

答えは返ってくる
学習した大量のコードから「この形のループはたいてい止まる」と見当をつけている。当たることは多い
しかし保証がない
間違っていても「分かりません」とは言わない（第13回）。どんな入力に対しても正しい、という保証がどこにもない
ライスの定理は、どんな方法をとってもその保証は得られないと述べている
学習データを増やしても、モデルを大きくしても、この壁は動かない。生成AIも静的解析も、迂回策の1つ目「近似する」をやっているにすぎない。

機械が答えを出せることと、その答えを信用してよいことは、違う。第13回で同じ問いをもう一度扱う。

まとめ

  • アルゴリズム有限性・明確性・実行可能性を満たす手順。「終わること」を確かめるのは、しばしば難しい
  • チューリングマシン紙と鉛筆の計算を極限まで単純化した機械。部品はテープ・ヘッド・有限個の状態しかない
  • 万能チューリングマシン他の機械の規則表をデータとして受け取り実行する。プログラム内蔵方式の原型
  • チャーチ＝チューリングのテーゼ計算モデルを変えても、計算できる範囲は広がらない
  • 量子計算機範囲は変えない。変えるのは速さで、その帰結が第12回の公開鍵暗号に効く
  • 停止問題計算できない。プログラムの振る舞いに関する自明でない性質は、すべて計算できない
  • 生成AIとの関係AIも静的解析も、この限界を「近似」で迂回しているにすぎない
