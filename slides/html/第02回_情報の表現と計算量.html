2.1　情報の表現

なぜ2進数なのか

2進数を使うのは、数学的に優れているからではない。物理的に作りやすいからである。

2状態なら1V以上の余裕がある。多少ばらついても間違えない。

読み取った時点で 0 か 1 に丸め直せば元通りになる。アナログはコピーのたびに劣化するが、
デジタルは何万回コピーしても、媒体を乗り換えても情報が保たれる。

2.1　情報の表現

ビットとバイト

n ビットあれば 2ⁿ 通りの状態を表せる。

ビット数状態数だいたい
82561バイト。文字1個、色の1成分
1665,536音声1サンプル
32約43億IPv4アドレス、整数1個

8である必然性は薄く、歴史的経緯による。厳密さが要る文脈では8ビットであることを明示して
「オクテット」と呼ぶ。通信規格の文書はほぼこちらを使う。

文字は「文字と番号の対応表」を決めて番号を2進数で表す。現在は UTF-8 が事実上の標準。

2.2　数の表現と誤差

負の数：2の補数

n ビットで、負数 −x を 2ⁿ − x として表す。−x は「全ビットを反転して1を足す」。

8ビットの例
10進2進
30000 0011
10000 0001
00000 0000
−11111 1111
−31111 1101
2の補数の利点

減算が要らない。a − b を a + (−b) として、加算回路だけで計算できる。
しかも符号を気にせず、桁あふれは捨てるだけでよい。

範囲は −2ⁿ⁻¹ 〜 2ⁿ⁻¹−1。8ビットなら −128 〜 +127。

127 + 1 は −128 になる

「大きい数に足したら負になった」というこの挙動は、現実に事故を起こしている。

2.2　数の表現と誤差

浮動小数点数には原理的な誤差がある

0.1 は2進数だと 0.0001100110011… と循環し、有限ビットでは表しきれない。

0.1 + 0.2 == 0.3 は偽になる。処理系のバグではなく、避けられない。

金額は浮動小数点数で扱わない（整数か十進小数型を使う）／等値比較をしない（|a−b| < ε で判定）
／大きな数と小さな数を足すと小さいほうが消えるので、合計は小さい順に足す

2.3　単位と桁の感覚

容量表示がずれる理由

「1キロバイト」は1000バイトか1024バイトか。両方の流儀があるのが混乱の元である。

2進接頭辞値SI接頭辞値ずれ
Ki（キビ）2¹⁰ = 1,024k（キロ）10³+2.4%
Mi（メビ）2²⁰M（メガ）10⁶+4.9%
Gi（ギビ）2³⁰G（ギガ）10⁹+7.4%
Ti（テビ）2⁴⁰T（テラ）10¹²+10.0%
1TB のドライブは 10¹² バイト。OS が 2⁴⁰ で割ると 0.91TB と表示される

誰も嘘はついていない。なお通信速度は昔から SI接頭辞。さらに b は bit、B は Byte。
1Gbps の回線で 1GB を送ると 8 Gbit ÷ 1 Gbps = 8秒（理論値）。

2.4　計算量

オーダの伸び方

入力の大きさ n に対して基本操作の回数がどう増えるかで測る。定数倍と低次の項は無視する。

定数倍は計算機を買い替えれば縮むが、オーダは何を買っても縮まない。

n を増やしたときの実感

1操作 1ns として。

n=100 で O(n²) と O(2ⁿ) の差は「10マイクロ秒」と「宇宙の年齢の1000倍」

計算機を100万倍速くしても、O(2ⁿ) の問題は n が20増える程度しか扱えるようにならない。

2.4　計算量

探索の例：線形探索と二分探索

線形探索　O(n)

先頭から順に見る。最悪 n 回。

n = 10億 のとき、最悪10億回。

二分探索　O(log n)

真ん中を見て、目的の値より大きければ左半分、小さければ右半分に絞る。毎回半分になるので log₂ n 回。

n = 10億 のとき、約30回。

3千万倍の差。これは実装の工夫では埋まらない。

2.4　計算量

P と NP

ここまでは個々のアルゴリズムの話だった。次は問題そのものを分類する。

クラス P
多項式時間 O(nᵏ) で解けるアルゴリズムが存在する問題。「現実的に解ける」問題の理論的な定義とされる
クラス NP
答えの候補を与えられたとき、それが正しいか多項式時間で「検証できる」問題
P = NP か？　2026年現在も未解決
クレイ数学研究所のミレニアム懸賞問題の1つ（賞金100万ドル）。P ⊆ NP は明らか（解けるなら検証もできる）。

巡回セールスマン問題は、経路を提示されれば正しさを確かめられるが、見つける方法は知られていない。

2.4　計算量

NP完全に当たったら

「その1つが多項式時間で解ければ、NP のすべての問題が解ける」問題群を NP完全という。SAT、巡回セールスマン、ナップサック、グラフ彩色、数独の一般化。

近似する
最適でなくてよいので、最適の2倍以内を保証する
問題を制限する
実際に現れる入力の性質を使う
ヒューリスティクス
保証はないが実際にはうまくいく手法（焼きなまし法、遺伝的アルゴリズム）
十分小さい n で妥協する
扱う規模を現実的な範囲に抑える

半世紀にわたり世界中の研究者が見つけられなかったものを、締切までに見つけられる見込みは薄い。

18
2.4　量子計算機

量子計算機は、この分類をどう変えるか

第1回で「範囲は変えないが速さを変える」と述べた。計算量の言葉が揃ったので正確に言い直す。古典的な計算機で多項式時間で解けるクラスが P、量子計算機で多項式時間で解けるクラスが BQP である。

P ⊆ BQP。量子計算機でできることは、古典的な計算機でも（遅いが）できる
  • 計算できる範囲 変わらない
  • 素因数分解 BQP には入る

だから第1回の「計算できる範囲は広がらない」が成り立つ。素因数分解は P に入るとは知られていないが、
Shor のアルゴリズムは量子計算機でこれを多項式時間で解く。

ここが最も誤解されるところである ——「量子計算機があれば NP完全問題も解ける」は誤りである。

19
2.4　量子計算機

NP完全は、量子計算機でも解けない

しらみつぶし探索を速くする Grover のアルゴリズムは、n 通りの探索を √n 回に減らす。しかし指数時間の問題では n が 2ᵏ である。

加速の程度
探索の手数    n    →  √n

指数時間なら  2^k  →  2^(k/2)

              指数時間のまま

鍵を1ビット伸ばせば元の強度に戻る

では Shor はなぜ効くのか

素因数分解が NP完全ではないからである。NP には属するが、P と NP完全の中間にあると見られている。量子計算機が効くと分かっているのは、この中間の領域である。

素因数分解と離散対数には「周期を見つける」構造がある

強みは「難しい問題を何でも速く解く」ことではなく、特定の構造を持つ問題に刺さること。第12回の暗号に効いてくる。

2.4　計算量

第1回との関係

計算できるか（第1回）と、現実的な時間で計算できるか（今回）は別の問い
  • 計算不可能 停止問題（第1回）
  • 指数時間しか知られていない NP完全（今回）
  • 多項式時間で解ける クラス P

この2段階の壁が、以降の講義に何度も顔を出す。第12回の公開鍵暗号は「素因数分解が P に属すると
知られていない」ことに安全性を託しているし、第13回の機械学習は「厳密に解けない問題を近似で押し切る」道具立てである。

まとめ

  • 2進数を使う理由ノイズに強いから。デジタル情報が劣化しないのはこの性質による
  • 量子計算機P ⊆ BQP で範囲は変わらない。NP完全も指数時間のまま。効くのは中間の問題
  • 2の補数減算が加算回路だけで済む。だから負数はこの形式で表す
  • 浮動小数点数原理的な誤差がある。等値比較をしない、金額に使わない
  • 接頭辞SI（10³）と2進（2¹⁰）の違いが、容量表示のずれを生む
  • 計算量入力規模に対する伸び方で測る。定数倍は買い替えで縮むが、オーダは縮まない
  • P と NPP は解ける問題、NP は検証できる問題。NP完全に当たったら近似・制限・ヒューリスティクスへ
