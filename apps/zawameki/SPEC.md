# ざわめき（Zawameki）仕様書

> **教室の「ざわめき」を、声を出さずに教員へ届ける。**

講義中の学生の理解度と質問を、リアルタイムに教員へ届ける Web アプリ。
学生はスマホでページを開き、学生番号を入れるだけでよい。アプリのインストールもパスワードも要らない。

版: 0.2（2026-10-05。P0 と投稿機能を実装した。動かし方は [README.md](README.md)）

| 決めたこと（2026-10-05） | 内容 |
| --- | --- |
| 受講者数 | 約200人 |
| 置き場所 | arena.koidelab.net の**別ポート（8100）**。**HTTPS**（arena の Caddy が 8100 番でも TLS を受け、アプリのコンテナへ渡す。証明書は arena と共用） |
| 学生番号 | **入力してもらう**（出席の記録）。ただし発言は匿名でできる |
| 投稿の種類 | 💬 コメント／❓ 質問／📣 ご意見申す／🔰 素人質問ですが の4つのボタン |

---

## 1. なぜ作るか

90分の講義で、教員に見えているのは学生の表情だけである。
大教室では「わからない」はほとんど声にならず、表情にも出ない。
気づくのは演習の答案を見た翌週で、そのときにはもう次の回に進んでいる。

ほしいのは次の3つである。

1. **いま**何人が迷っているか（講義を止めて説明し直すべきか）
2. **どこで**迷ったか（翌年どのスライドを直すべきか）
3. **何が**わからないのか（質問の中身）

## 2. これまでのアプリとの違い

| | これまで（LectureWebApp001 / CommBoard001 / arena など） | ざわめき |
| --- | --- | --- |
| 通信 | リクエスト／レスポンス（フォームを送ると返る） | **常時接続**（WebSocket）。サーバから押し出す |
| 利用者 | 1人ずつがログインして使う | **数百人が同時に1つの部屋**に入る。学生番号を入れるだけで、パスワードは無い |
| 主役のデータ | 投稿・回答・採点 | **時系列の信号**（何秒に何人が迷ったか） |
| 時間 | 締切まで | **90分で終わる**。部屋は講義ごとに作って閉じる |
| 教員の見方 | 一覧を読む | **ちらっと見て1秒でわかる**（天気で表す） |

市販の投票ツール（Slido、Mentimeter、Kahoot! など）とも違う。
それらは**教員が問いを出した瞬間しか測れない**。
ざわめきは、講義の90分間ずっと流れている信号を測る。

## 3. 一線

**ざわめきの記録は、成績に使わない。迷子ボタンと投稿は、誰のものか分からないようにする。**

「迷子です」と押せるのは、誰が押したか分からないからである。
押したことや書いたことが少しでも成績に結びつくと、学生は押さなくなり、信号そのものが死ぬ。
理由と運用は [assessment/README.md](../../assessment/README.md) の「AI は点数をつけない」と同じ立場であり、
**初回の講義で学生にもこの一線を明示する**。

- 入室のときに**学生番号**を入れてもらう。使うのは**出席の記録**（誰がその回に入室したか）だけ
- 迷子・ペースの信号は集計値だけを残す。**投稿の表には学生番号の列を持たない**
- 学生が自分で「学生番号を添える」を選んだ投稿だけ、教員に学生番号が見える（他の学生には見えない）。既定は匿名で、1回ごとに外れる
- 「同じく」の重複を防ぐ票は鍵つきハッシュで持ち、**部屋を閉じたら捨てる**
- 氏名・メールは取らない

## 4. 使う場面（90分の流れに沿って）

[curriculum.md の90分の標準構成](../../docs/curriculum.md) に合わせる。

| 時間 | 教員 | 学生 | ざわめきの役割 |
| --- | --- | --- | --- |
| 開始前 | 部屋を開き、QR を投影する | QR を読んで入室する | 入室 |
| 0–10分 | 前回の復習 | — | **前回の「いちばんの謎」を見せる**（§5.6） |
| 10–80分 | 3つのブロックを話す | 迷ったら押す。質問を書く | **天気・ペース・質問**（§5.1〜5.4） |
| 区切りごと | 確認問題を1問出す | 答えと自信を選ぶ | **自信つき確認問題**（§5.5） |
| 80–90分 | 演習・まとめ | 1分カードを書く | **今日いちばんの謎**（§5.6） |
| 講義後 | レポートを見る | — | **迷子の地図**（§5.7） |

## 5. 機能

### 5.1 迷子ボタン（減衰する信号）

学生の画面のいちばん大きなボタン。

| ボタン | 意味 | 効き方 |
| --- | --- | --- |
| 😵 **迷子** | いま話がわからない | **90秒で自然に消える**。もう一度押すと90秒延びる |
| 💡 **わかった！** | さっきまで迷っていたが、わかった | 自分の「迷子」を消す。「ひらめき」として数える |

**減衰させるのがこのアプリの肝である。**
押しっぱなしの古い信号が残ると、教員は「もう説明し直したのに、まだ赤い」と惑う。
減衰させれば、教員に見えるのは「**いま**わからない人の数」だけになる。
学生の画面には残り時間を輪で示し、消える前に「まだ迷子？」とそっと聞く。

### 5.2 教室の天気

教員の画面は、数字ではなく天気で示す。話しながらちらっと見て1秒でわかるようにするため。

迷子率 *L* = 迷子の信号が生きている人数 ÷ 在室人数

| 天気 | 条件 | 教員がすること（目安） |
| --- | --- | --- |
| ☀️ 快晴 | *L* < 5% | そのまま進む |
| 🌤 晴れ | *L* < 10% | そのまま進む |
| ☁️ くもり | *L* < 20% | 次の区切りで一言補う |
| 🌧 雨 | *L* < 35% | 例を1つ足す |
| ⛈ 雷 | *L* ≥ 35% | 止めて、説明し直す |

- **少人数の教室で1人が押しただけで雷にならないよう**、迷子が3人未満なら「晴れ」より悪くしない
- くもり以上が30秒続いたら、教員の端末を1回だけ振動させる（設定で切れる）
- **学生の画面にも天気を出す**（既定オン）。「迷っているのは自分だけではない」と分かれば押しやすくなる

#### ひらめきの花火

迷子率が60秒以内に半分以下に下がり、かつ「わかった！」が5人以上のとき、
教員と学生の両方の画面に小さな花火を上げ、「**いまの説明で 14人が わかった**」と出す。
教員にとっては「説明し直した甲斐があった」ことがその場でわかる。これがこのアプリでいちばん楽しいところである。

### 5.3 ペースの綱引き

「🐢 遅い」「🐇 速い」の2つのボタン（60秒で減衰）。
教員の画面には、左右に引き合う1本の棒として出す。
迷子とは別の信号にする。**「わからない」と「速い」は原因が違う**ため。

### 5.4 投稿（4つのボタン）と「同じく」

学生は本文を書いてから、4つのボタンのどれかで送る。**どれも匿名**である。

| ボタン | 使いどころ | 字数 | 送れる間隔 | 他の学生が押せるもの |
| --- | --- | ---: | --- | --- |
| 💬 コメント | 感想・つぶやき。流れて消えてよいもの | 80 | 教員が決める（既定10秒） | なし |
| ❓ 質問 | わからないこと | 200 | 質問・意見あわせて1人30秒に1件 | 🙋 同じく |
| 📣 ご意見申す | 「ここはこうしたほうがよい」 | 200 | 〃 | 同感 |
| 🔰 素人質問ですが | 基本すぎて聞きにくいこと | 200 | 〃 | 🙋 同じく |

**「素人質問ですが」を独立したボタンにしたのは、聞くための敷居を下げるためである。**
「こんな基本的なことを聞いてよいのか」という遠慮を、ボタンの名前で先に許しておく。
（学会の「素人質問で恐縮ですが」がたいてい鋭い質問であることへの目配せでもある。投影ではこの前置きを添えて出す）

- 質問・ご意見・素人質問には、そのとき表示していたスライド番号が付き、「同じく」「同感」の多い順に教員へ届く
- 教員の操作: 「✓ 答えた」「あとで」「隠す」「未対応に戻す」。隠した投稿は全員の画面から消える
- コメントは教員が受付を止められる（止めても質問・意見は送れる）
- 荒らし対策: 送れる間隔、字数、NG語の伏せ字（`ZAWAMEKI_NG_WORDS`）、1本の接続から1秒8通まで
- 投影画面には「入室 QR」「質問・意見ボード（上位6件）」「流れるコメント」の3つを出せ、教員の操作画面から切り替える

### 5.5 自信つき確認問題

区切りで教員が1問出す。学生は答えと一緒に**自信**を選ぶ（自信あり／半々／勘）。
結果は「正誤 × 自信」の4象限で出す。

| | 正解 | 不正解 |
| --- | --- | --- |
| **自信あり** | 定着している | ⚠️ **自信満々の誤解** — いちばん危ない |
| **自信なし** | まぐれかもしれない | まだ習っていない |

**「自信満々の誤解」を見つけるのが目的である。** 正答率だけでは見えない。

さらに、正答率に応じて次の一手を提案する（Mazur のピア・インストラクションの目安による）。

| 正答率 | 提案 |
| --- | --- |
| 70% 超 | 次へ進む |
| 30–70% | 「**隣の人と2分話して、もう一度**」→ 再投票し、前後の変化を出す |
| 30% 未満 | 説明し直す |

問題は [moodle/numeric.js](../../moodle/numeric.js) の数値・選択の解答欄を取り込める（`pick` と `num` の問題）。
その場で作る2択・4択も出せる。

### 5.6 1分カード「今日いちばんの謎」

講義の最後に、1行だけ書いてもらう（任意）。
次の回の冒頭（0–10分の復習）で、教員はそれを開いて答えるところから始められる。

### 5.7 迷子の地図（講義後のレポート）

講義が終わると、スライド番号ごとに次をまとめた1枚が残る。

- 迷子の信号の山（スライド番号 × 時間の帯）
- そのスライドで出た質問と「同じく」の数
- 確認問題の結果（4象限）
- 1分カード

**翌年の資料改訂に直結させる。** Markdown で書き出し、
[docs/annual-update.md](../../docs/annual-update.md) と並べて「どのスライドを直すか」の根拠にする。
回を重ねれば、全13回のどこで毎年迷子が出るかが見えてくる。

## 6. スライドとの同期

迷子の信号と質問に「どのスライドのときか」を付けるには、教員がいまどのスライドを出しているかを知る必要がある。

| 方式 | 中身 | 位置づけ |
| --- | --- | --- |
| **A. HTML スライドから送る** | [slides/html/](../../slides/html/) のスライドは `show(i)` でページを切り替えている。そこに数行足し、URL に `?zawa=部屋コード&key=教員鍵` があるときだけ、切り替えをサーバへ送る | **本命**。教員は何もしなくてよい |
| B. 教員の画面で手送り | 教員の画面の ← → で節（1.1、1.2 …）を進める | pptx で話す回の予備 |
| C. 時刻から推定 | 講義ノートの「時間配分」表から、経過時間で節を推定する | A も B もないときの最後の手段 |

スライドの題名は [slides/decks/lecNN.js](../../slides/decks/) から読む。
迷子の地図で「スライド 23」ではなく「1.2 チューリングマシン — 状態遷移表」と出すため。

A の変更は [slides/tools/kit-html.js](../../slides/tools/kit-html.js) に入れる。
`?zawa=` が無ければ何もしないので、普段のスライドの動作は変わらない。

## 7. 画面

| 画面 | 誰が | 端末 | 中身 |
| --- | --- | --- | --- |
| 入室 | 学生 | スマホ | 部屋コード4桁（QR なら不要）、学生番号、一線の説明、「入る」 |
| 学生 | 学生 | スマホ | 迷子／わかった！（大）、遅い／速い、天気、投稿欄と4つのボタン、流れ／質問・意見のタブ、確認問題（出たときだけ） |
| 教員操作 | 教員 | タブレット・PC・スマホ | 天気（大）、迷子率の直近10分の線、ペース棒、質問上位3件、確認問題を出す、節の手送り |
| 投影 | 教員 | プロジェクタ | 入室用 QR、質問・意見ボード、流れるコメント、確認問題の結果。教員操作で切り替える |
| レポート | 教員 | PC | 迷子の地図、質問一覧、確認問題、1分カード。Markdown/CSV で書き出し |

画面の約束:

- 学生画面は**片手の親指で押せる**位置にボタンを置く。講義中に目を離す時間を最短にする
- 色だけで区別しない（天気はアイコンと文字も添える）
- 暗い教室で眩しくないよう、ダークモードを既定にする
- 学生画面は 100 KB 以下。教室の Wi-Fi が弱くても開けるように

## 8. 仕組み

### 8.1 構成

```
 学生のスマホ ×200 ──┐
                    ├─ WebSocket ─→  サーバ（1プロセス）──→ SQLite
 教員の端末 ─────────┤                 部屋ごとの状態はメモリに持つ
 HTML スライド ──────┘                 1秒ごとに集計して配る
```

| 層 | 選ぶもの | 理由 |
| --- | --- | --- |
| サーバ | **Python 3.13 + FastAPI + WebSocket**（uvicorn） | これまでのアプリと同じ言語で保守できる。200接続なら1プロセスで足りる（実測は README） |
| 保存 | SQLite | 部屋は講義中しか生きない。重い DB は要らない |
| 画面 | 素の HTML + JavaScript（ビルド工程なし） | スライドの HTML 版と同じく、ファイルを置けば動く |
| 配備 | Docker Compose | arena と同じ手順で置ける。arena.koidelab.net のポート 8100 |

**状態は部屋ごとにメモリに持ち、1秒に1回だけ集計して配る。**
学生が押すたびに全員へ配ると、200人 × 200人で通信が膨れるため。
出来事（投稿など）も 0.25 秒ごとにまとめて配る。

- 教員の画面へ: 1秒ごと
- 学生の画面へ: 5秒ごと（天気と自分の残り時間だけ）
- 質問・確認問題・花火: 起きたときにすぐ

### 8.2 通信の取り決め（WebSocket、JSON）

学生 → サーバ

| type | 中身 |
| --- | --- |
| `hello` | `{code, sid}`。sid は学生番号。再接続でも同じものを送る |
| `lost` / `got` | 迷子／わかった！ |
| `pace` | `{dir: "slow" \| "fast"}` |
| `post` | `{kind: "comment" \| "question" \| "opinion" \| "naive", text, named}` |
| `metoo` | `{id}` |
| `answer` | `{quiz, choice \| value, confidence}`（P2） |
| `card` | `{text}`（1分カード、P3） |

教員・スライド → サーバ（教員鍵が必要）

| type | 中身 |
| --- | --- |
| `hello` | `{code, key}`。鍵は URL に載せず最初の1通で送る（ログに残さない） |
| `slide` | `{no}` |
| `mark` | `{id, status: "open" \| "answered" \| "later" \| "hidden"}` |
| `settings` | `{comments_open, comment_interval, show_weather}` |
| `projector` | `{mode: "join" \| "board" \| "stream"}` |
| `quiz_open` / `quiz_close` | 確認問題を出す／締める（P2） |

部屋を閉じるのは HTTP（`POST /api/teacher/rooms/{code}/close`）で行う。

サーバ → 全員

| type | 中身 |
| --- | --- |
| `tick` | `{present, lost, aha, slow, fast, weather, slide}`（学生には在室・天気・スライドだけ） |
| `post` / `post_removed` | 投稿の追加・更新／隠した投稿を消す（教員には記名と隠した投稿も） |
| `quiz` / `quiz_result` | 問題／4象限の集計 |
| `fireworks` | `{count}` |

### 8.3 保存するもの

| 表 | 列 |
| --- | --- |
| `rooms` | id, code, key, title, opened_at, closed_at, slide, settings |
| `attendance` | room_id, student_id, joined_at — **出席の記録。投稿とは結びつかない** |
| `ticks` | room_id, t（秒）, slide, present, lost, aha, slow, fast — **集計値だけ** |
| `slides` | room_id, t, no, title |
| `posts` | room_id, id, t, slide, kind, text, named（記名したときだけ）, status, votes |
| `post_votes` | room_id, pid, voter（鍵つきハッシュ）— 部屋を閉じたら消す |
| `quizzes` / `answers` | 問題と、選んだ答え・自信（端末は記録しない） |
| `cards` | room_id, text |

学生番号と投稿を結ぶ情報は、講義中のメモリ（送信間隔の制限に使う）にしか無く、表には書かない。

### 8.4 部屋と鍵

- 教員が部屋を開くと、**部屋コード4桁**と**教員鍵**（長い乱数）が出る
- 部屋コードは講義ごとに変わる。閉じた部屋には入れない。開いたまま4時間たつと自動で閉じる
- 教員の入口（`/teacher`）は Basic 認証で守る（arena と同じ）。部屋を開け閉めする POST には独自ヘッダ `X-Zawameki` を必須にする（ブラウザは Basic 認証を他サイトからの送信にも付けるため。CSRF 対策）
- 投影画面は URL の `#key=` で教員鍵を受け取る（`#` の後ろはサーバにも Referer にも送られない）。教室の PC で Basic 認証を求めないため
- 学生番号の本人確認はしない。他人の番号でも入れるが、記録を成績に使わないのでこれで足りる

## 9. 守ること（非機能）

| 項目 | 目標 |
| --- | --- |
| 同時接続 | 1部屋200人。`tools/loadtest.py` で確かめた（README） |
| 遅れ | 押してから教員の画面に出るまで2秒以内 |
| 回線断 | 自動で再接続し、自分の状態（残り時間）を取り戻す |
| 端末 | iOS Safari / Android Chrome の直近2版。インストール不要 |
| 言語 | 日本語と英語（[lectures-en/](../../lectures-en/) があるため） |
| 安全 | 投稿の本文は必ず textContent／エスケープで出す（第10回・第12回で教える XSS をここで起こさない）。CSP で `script-src 'self'` に絞る。送信量に上限を設ける |

## 11. 後回しにすること

- **似た質問をまとめる AI**: 質問が30件を超えたとき、似たものを束ねて講義ノートの節に紐づける。
  arena と同じく Ollama（ローカル）で動かせば、質問の本文を外に出さずに済む。
  ただし **AI は学生に直接答えない**。束ねるだけで、答えるのは教員である
- 出欠を成績に使う仕組み: 入室の記録（学生番号と時刻）は CSV で出せるが、それを成績にどう使うかはアプリの外で決める。迷子ボタンや投稿の記録は使わない（§3）
- Moodle との連携（LTI）: ログインが要るようになり、匿名性と両立しにくい。必要が出たら考える
