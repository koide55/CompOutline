# コンピュータシステム通論 カリキュラム設計（90分 × 13回）

## 設計方針

### 何を目指すか

この講義の目的は、個々の技術の使い方を覚えることではない。
**「計算とは何か」から出発して、目の前の計算機やインターネット、そして生成AIまでが
すべて同じ原理の上に立っていることを見通せるようになること**である。

そのため全13回を一本の線で貫く。

```
計算の定義（第1回）
  → 情報の表し方と、計算の「重さ」（第2回）
    → 原理を電子回路で実現する（第3回）
      → 人間の言葉から機械の言葉へ（第4回）
        → 速くするための階層構造（第5・6回）
          → 資源を共有するための管理機構（第7・8回）
            → 計算機どうしをつなぐ（第9・10回）
              → データを溜めて守る（第11・12回）
                → そして計算機は「学習」する（第13回）
```

### 90分の標準構成

各回はこの型で組む。

| 時間 | 内容 |
| --- | --- |
| 0–10分 | 前回の復習と、今回の問い（この90分で答えを出す1つの問い） |
| 10–35分 | 第1ブロック |
| 35–60分 | 第2ブロック |
| 60–80分 | 第3ブロック |
| 80–90分 | 演習・まとめ・次回予告 |

演習は各回5〜10問。手を動かして数値を出す問題を必ず1問入れる
（計算機科学は「桁の感覚」が身につかないと理解が定着しないため）。

**演習の解答とポートフォリオは、毎回 Moodle で提出してもらう。
これが成績であり、出席でもある**（2026年度後期）。

## 全13回

### 第1回 計算とは何か

**問い**: 「計算できる」とはどういうことか。計算できないことはあるか。

アルゴリズムの定義から始め、チューリングマシンという極端に単純な機械が
「計算」の全体を捉えていることを見る。チャーチ＝チューリングのテーゼ、
そして停止問題によって計算の限界を示す。

キーワード: アルゴリズム、チューリングマシン、状態遷移、万能チューリングマシン、
チャーチ＝チューリングのテーゼ、決定不能、停止問題

### 第2回 情報の表現と計算量

**問い**: 情報を2進数で表すと何が嬉しいのか。「速いアルゴリズム」とは何か。

前半で情報の表現（2進数、負数、浮動小数点、文字コード、単位）を、
後半で計算量（O記法、P と NP）を扱う。第1回の「計算できるか」に対して、
第2回は「現実的な時間で計算できるか」を問う。

キーワード: ビット、バイト、2の補数、IEEE 754、Unicode、SI接頭辞と2進接頭辞、
O記法、多項式時間、P、NP、NP完全

### 第3回 論理回路からプロセッサへ

**問い**: 数学的なモデルを、どうやって電気で作るのか。

論理ゲートから加算器と記憶素子を組み立て、ノイマン型計算機の構成に至る。
命令の実行サイクルを追い、素子の変遷（真空管→トランジスタ→IC）と
ムーアの法則で締める。

キーワード: 論理ゲート、NAND完全性、半加算器・全加算器、フリップフロップ、
ノイマン型、命令実行サイクル、レジスタ、ムーアの法則、デナード則の終焉

### 第4回 プログラムが動くまで

**問い**: 人間が書いた文字列が、なぜ機械の動作になるのか。

機械語・アセンブリ・高級言語という抽象化の階段を上り、
コンパイラ、インタプリタ、仮想機械、JIT の違いを整理する。
言語の分類と系譜も扱う。

キーワード: 機械語、アセンブリ、コンパイラ、インタプリタ、リンク、
実行ファイル、仮想機械、JIT、手続き型・関数型・オブジェクト指向、型システム

### 第5回 記憶階層とプロセッサの並列性

**問い**: なぜ計算機の速度は「メモリ待ち」で決まるのか。

SRAM/DRAM の原理、参照の局所性、キャッシュ、仮想記憶を扱い、
後半でパイプライン・スーパースカラ・マルチコア・SIMD/GPU という
並列性の階層を見る。

キーワード: 記憶階層、SRAM、DRAM、リフレッシュ、参照の局所性、キャッシュライン、
ヒット率、仮想記憶、ページング、パイプライン、スーパースカラ、マルチコア、SIMD、GPU

### 第6回 ストレージとファイルシステム

**問い**: 電源を切っても消えないデータは、どう置かれているのか。

磁気ディスクの物理構造とアクセス時間の見積もり、
フラッシュメモリと SSD/NVMe、冗長化（RAID）、ファイルシステム、
そして現代の分散ストレージまで。

キーワード: シリンダ・トラック・セクタ、シーク時間、回転待ち、フラッシュメモリ、
ウェアレベリング、NVMe、RAID 0/1/5/6、パリティ、ファイルシステム、
オブジェクトストレージ、イレイジャーコーディング

### 第7回 オペレーティングシステムとプロセス

**問い**: 1台の計算機を、なぜ何十ものプログラムで同時に使えるのか。

OS の役割、カーネルとユーザ空間、システムコール、
プロセスとスレッド、スケジューリング、そして同期とデッドロック。

キーワード: カーネル、特権モード、システムコール、プロセス、アドレス空間、
コンテキストスイッチ、ファイル記述子、パイプ、スレッド、スケジューリング、
排他制御、デッドロック

### 第8回 入出力・仮想化・クラウド

**問い**: 100万倍遅い装置と、どうやって折り合いをつけるのか。

CPU と周辺装置の速度差から割り込みと DMA の必然性を導き、
デバイスドライバによる抽象化、さらに「計算機そのものを抽象化する」
仮想化とコンテナ、その上に立つクラウドへ。

キーワード: 割り込み、ポーリング、DMA、デバイスドライバ、
ハイパーバイザ、仮想機械、コンテナ、イメージ、オーケストレーション、
IaaS/PaaS/SaaS、責任共有モデル

### 第9回 ネットワークの基礎

**問い**: 世界中の計算機が、なぜ1つの網としてつながるのか。

パケット交換の考え方、階層モデル、インターネットの構成（AS と IX）、
物理層とデータリンク層（Ethernet、Wi-Fi、MACアドレス、スイッチ）、
そしてインターネット層（IP アドレス、ルーティング、NAT、IPv6）。

キーワード: パケット交換、プロトコル、階層モデル、カプセル化、
AS、IX、Ethernet、フレーム、MACアドレス、スイッチ、CSMA/CD、Wi-Fi、
IPアドレス、サブネット、ルーティング、ベストエフォート、NAT、IPv6

### 第10回 インターネットとWeb

**問い**: 名前しか知らない相手と、失われるかもしれない経路の上で、
どうやって確実に、そして安全にやりとりするのか。

UDP と TCP、ポート、ソケット、DNS、
そして HTTP と TLS、Webアプリケーションの構成、
クライアントサーバと P2P、CDN。

キーワード: UDP、TCP、3ウェイハンドシェイク、輻輳制御、ポート、ソケット、DNS、
HTTP/1.1・HTTP/2・HTTP/3、QUIC、TLS、REST、CDN、P2P

### 第11回 データベースとデータ処理

**問い**: 壊れずに、矛盾なくデータを溜めるにはどうするか。

リレーショナルモデル、SQL、正規化、トランザクションと ACID、
そして大規模化にともなう NoSQL・分散データ処理、
意味の近さで探すベクトル検索（第13回の RAG の土台）へ。

キーワード: リレーショナルモデル、主キー・外部キー、正規化、SQL、結合、
トランザクション、ACID、同時実行制御、レプリケーション、シャーディング、
NoSQL、CAP定理、MapReduce、ベクトル検索、近似最近傍探索、RAG

### 第12回 情報セキュリティ

**問い**: 顔の見えない相手を、どうやって信用するのか。

共通鍵・公開鍵暗号、ハッシュ、ディジタル署名、証明書と PKI、
量子計算機が公開鍵暗号に与える影響と耐量子計算機暗号への移行、
認証と認可の区別、多要素認証とパスキー、シングルサインオン、
そして現実の脅威とゼロトラスト。

キーワード: 機密性・完全性・可用性、共通鍵暗号、公開鍵暗号、ハッシュ関数、
ディジタル署名、X.509証明書、認証局、認証と認可、多要素認証、FIDO2/パスキー、
OAuth 2.0、OpenID Connect、ゼロトラスト、ランサムウェア、サプライチェーン攻撃、
Shor のアルゴリズム、耐量子計算機暗号、ML-KEM、ハイブリッド鍵交換

### 第13回 機械学習からLLM・エージェントAIへ

**問い**: 計算機が「学習する」とはどういう計算か。第1回のチューリングマシンとどう繋がるか。

機械学習の位置づけ、ニューラルネットワークと誤差逆伝播、
トランスフォーマと自己注意、LLM の学習過程、
そしてツールを使い自律的に動くエージェントAIと、その社会的な論点。

キーワード: 機械学習、教師あり学習、ニューラルネットワーク、誤差逆伝播、
深層学習、トランスフォーマ、自己注意、トークン、事前学習、ファインチューニング、
スケーリング則、ハルシネーション、RAG、ツール利用、エージェント、AIガバナンス

### `network2026.pptx`（通信工学概論）から取り込んだもの

同じディレクトリにある別講義のスライドに、本講義に欠けていた
「システムコールを実際に呼ぶ」話があったので、要点だけ移した。

| 旧セクション | 移行先 | 内容 |
| --- | --- | --- |
| システムコールプログラミング（旧 slide 537–550） | 第7回 7.2 | ファイル記述子、pipe、dup、シェルの `\|` の仕組み |
| ソケットプログラミング（旧 slide 551–570） | 第10回 10.1 | socket / bind / listen / accept / connect の順序 |

旧スライドは2006年時点の記述で、`sockaddr_in` を手で埋める C の作法が
中心だった。本講義は通論なので、**呼び出しの順序と役割**だけを残し、
コードの詳細は落とした。IPv4 前提の記述は `getaddrinfo` に置き換えた。

## 執筆上の約束

- **第三者著作物は使わない。** 図はすべて `figures/README.md` の仕様に従って自作する。
  製品写真・報道写真・Web からの引用図は載せない。
- **具体的な数値には時点を書く。** 「2026年時点で」と明記し、
  毎年の更新箇所を `docs/annual-update.md` に集約する。
- **個人情報を例に使わない。** メールアドレスは `example.com`、
  IPアドレスは RFC 5737 の文書用アドレス（`192.0.2.0/24` 等）を使う。
